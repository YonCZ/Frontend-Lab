# Design plan

Software. Frontend Lab is a local build comparison tool. Its main action is to open a build.

## Shared rules

Use the supplied three projects and their exact counts. Read actual build metadata for entry paths. Test 1 includes four existing DeepSeek builds. Use screenshots of the actual local entry pages. Voice is technical and direct. Interface labels name the action. The brief expands in place. Selection and the pinned build remain separate state. All variants support keyboard focus, Escape, a full-window preview, and a stacked phone layout.

The brief overrides the taste kit's landing-page recipes, random palette deals, asset kit, hero entrances and motion requirements. A workbench has no sales hero, effects or promotional sections. The starter remains the only copied project code.

## Variant 1

White #ffffff, ink #222724, muted #65716a, surface #f0f2f0, accent #216747. Instrument Sans for controls and text, Instrument Serif for the library title. A wide index aligns each project name, one-line brief, model list and build count. Small initial covers give rows an anchor. Project builds use compact screenshot tiles.

Library: heading and search above aligned project rows.
Project: title, expandable brief, filters, screenshot grid.

## Variant 2

White #ffffff, ink #20242b, muted #656d78, surface #eff1f4, accent #2456b8. Public Sans throughout. Large neutral initial covers form an open grid. Build screenshots are larger and have no enclosing card border. Titles and metadata stay left aligned.

Library: heading beside search, then three open tiles.
Project: title beside brief, then larger screenshot tiles.

## Variant 3

White #ffffff, ink #262624, muted #6c6c65, surface #f1f1ee, accent #9b451f. Instrument Sans throughout. A persistent library rail reduces navigation overhead. The project view puts a readable brief column beside a dense build grid.

Library: navigation rail beside project rows.
Project: navigation rail, brief column, build grid.

## Critique before build

Removed decorative counters, file-tree icons and cover ornaments. Initial covers represent projects without inventing imagery. Each layout has a practical density choice rather than only a different palette. Counts and build metadata stay visible. Whitespace separates groups before borders do.
